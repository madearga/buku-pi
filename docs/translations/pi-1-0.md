Hari ini kami dengan bangga merilis Pi 1.0: sebuah Agent Harness yang sudah dipoles matang, minimalis, dapat diperluas, dan dapat Anda bentuk sendiri. Setiap minggu, ratusan ribu orang di seluruh dunia memakai Pi. Banyak di antara Anda mengirimkan issue dan Pull Request. Beberapa bulan terakhir ini kami terus memperbaiki, memperkuat, dan mengembangkan Pi berdasarkan masukan itu, sehingga ia menjadi perangkat lunak stabil yang dapat diandalkan baik oleh perorangan maupun perusahaan.

Pi dikenal minimalis, dan kami sangat berhati-hati menjaga hal itu. Tool Agent berubah setiap minggu, tetapi banyak perubahan tidak bertahan lama. Pendekatan Pi berbeda: kami menunggu sampai sesuatu membuktikan nilainya, baru mempertimbangkan apakah akan mengadopsinya, sambil menimbang kemampuan yang sebenarnya diberikannya dengan kompleksitas yang pasti bertambah. Awal minggu ini kami [membahas proses itu lebih jauh di artikel ini](/translations/you-said-no-mcp), termasuk kaitannya dengan Codemode dan MCP.

Pi 1.0 yang dirilis hari ini adalah hasil dari proses tersebut. Pi sudah dapat menjalankan model terbaru dari berbagai penyedia utama, menjadi asisten pemrograman yang dipakai setiap hari oleh pengguna di seluruh dunia, dan juga menyediakan fondasi yang sangat mudah dibentuk untuk membangun aplikasi Agent. Bersamaan dengan rilis Pi 1.0, kami menghadirkan kemampuan berikut ke dalam Pi:

- Codemode: dukungan asli untuk MCP, sekaligus dukungan untuk model non-LLM seperti Jev dan model gambar.
- Ekstensi dapat menyediakan model virtual.
- Pemuatan tool secara bertahap.
- Pemanasan cache untuk model Anthropic.
- Pesan sistem di tengah percakapan: agar perubahan prompt dan tool tercermin dalam catatan transkrip.
- Tema antarmuka terminal baru.
- Mode layar penuh sebagai bawaan.

Sebagian besar fitur itu sudah kami pikirkan selama berbulan-bulan. Semuanya dicoba, dan akhirnya bertahan; percobaan yang tidak bertahan jauh lebih banyak. Ketika kami memakai Pi dengan fitur-fitur baru ini, kami merasakan langkah besar ke depan, tetapi ia tetap sederhana, tetap Pi.

Sambil terus memoles dan mengembangkan Pi, kami juga mulai menyadari bahwa beberapa bentuk Pi tidak cocok dengan cara banyak orang ingin memakainya. Di Earendil, kami ingin membawa prinsip minimalis Pi, serta cara Pi membuat Anda mengendalikan AI, ke luar batas asisten pemrograman dan terminal. Ia perlu dapat diakses dari berbagai antarmuka, dan mendukung percakapan serta tugas yang berjalan lebih lama. Artinya, Pi perlu menjadi lebih tahan lama dan andal. Agar tidak menyimpang dari akar minimalisnya, dan tidak memaksa Pi menjadi sesuatu yang lain, kami mengemas pekerjaan itu menjadi paket eksperimental baru yang juga dirilis hari ini: Pi Durable.

Pi Durable adalah fondasi baru untuk membangun aplikasi Agent yang berjalan lama, sehingga pengembang dan pengguna aplikasi tersebut dapat dengan luwes memakai dan mengarahkan kecerdasan di belakangnya. Ia berbagi prinsip inti Pi—minimalis dan sangat mudah dibentuk—sekaligus memperluas prinsip itu ke dimensi baru. Mario [di sini](/translations/pi-durable) menjelaskan secara rinci bagaimana kami membangun Pi Durable.

Earendil didirikan untuk membangun perangkat lunak dan protokol terbuka yang memperkuat otonomi manusia. Hari ini, kami menyerahkan alat untuk mencapai tujuan itu ke tangan Anda semua. Kami menantikan masukan Anda, dan menantikan bersama-sama menguasai masa depan secara terbuka.

Pi 1.0 dapat dipasang hari ini:

``` sh
curl -fsSL https://pi.dev/install.sh | sh
```

Pengguna Windows dapat menjalankan:

``` powershell
powershell -c "irm https://pi.dev/install.ps1 | iex"
```

Pi Durable juga tersedia hari ini sebagai paket eksperimental:

``` sh
npm install @earendil-works/pi-durable @earendil-works/pi-ai @earendil-works/chord
```

Keduanya memakai lisensi MIT. Dokumentasi tersedia di [pi.dev](https://pi.dev), dan kodenya di [github.com/earendil-works/pi](https://github.com/earendil-works/pi).

**Langkah pada rekaman terminal asli**

1. Codemode: Pi menulis skrip untuk merapikan commit selama sepekan menjadi ringkasan singkat.
2. Pi menulis Ekstensi untuk dirinya sendiri: model virtual yang merencanakan lebih dulu dengan Claude Opus lalu mengimplementasikan dengan GPT, dan Jev yang menentukan kapan harus beralih.
3. Muat ulang, buka sesi baru, lalu pilih model `router/auto` yang baru.
4. Merencanakan dengan Claude Opus.
5. Jev mengenali bahwa pekerjaan sudah masuk tahap implementasi, lalu menyerahkannya ke GPT 6 Luna.
6. Jalankan skrip yang sudah selesai dengan `!`.
7. `/session` menampilkan biaya dan pemakaian cache untuk setiap model.

Rekaman terminal asli dapat diputar di [halaman Pi 1.0 milik Earendil](https://earendil.com/posts/pi-1-0/).
