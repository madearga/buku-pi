# Pi 1.1.0 release highlights

Pi 1.1.0 was released on **7 October 2026**. This page is compiled from the official changelog and the pinned-version documentation, verified on **2026-10-11**. The complete item-by-item English changes are kept in the [release archive](/en/releases/#release-v1-1-0).

Between 1.0.0 and 1.1.0 there were four more small releases, 1.0.1 through 1.0.4. If you are upgrading straight from 1.0.0, you will run into the changes listed in the second half as well. For what 1.0.0 itself changed, see [Pi 1.0.0 release highlights](/en/releases/pi-1-0).

## Changes worth noting in 1.1.0

| Change | What it means for you |
| --- | --- |
| Default tools can be added and removed | When `--tools` is a list containing only `+name` and `-name` entries, Pi adds to or removes from the default tools instead of replacing the whole set |
| OSC 7501 program status | In a terminal or Agent panel that supports the protocol, you can see whether Pi is working, waiting for you, finished, or failed |
| Claude Haiku 5.5 | Adds `anthropic/claude-haiku-5-5`, with thinking strength up to `xhigh` / `max` |
| Classify model | GPT-6 Luna can be used as the classify model; Codemode's `models.classify()` can take images, as long as the chosen classify model supports them |
| `/mcp` no longer waits for every connection | In the MCP management screen, server connection states update in real time instead of waiting for all servers to connect |
| `pi update` cleans up old versions | For installations managed by the official installer, an update keeps only the new version and the previous one |

The classify model only judges and classifies; it is not the main model you chat with. For everyday conversation and code changes, you do not need to adjust anything because of this change.

## The plus/minus syntax for default tools

Pi enables the four tools `read`, `bash`, `edit`, and `write` by default. To add one more tool in the past, you had to list every tool you wanted all over again; from 1.1.0 you can write only the adjustments you want:

```bash
pi --tools +codemode,-write
```

This command keeps the other default tools, additionally enables `codemode`, and turns off `write`. Three things to watch:

- Plain names and the `+`/`-` syntax cannot be mixed; as soon as a plain name appears, the full-list replacement still applies.
- After `+`/`-` you can only write exact tool names, not `*` wildcards; to remove tools by wildcard, use `--exclude-tools` instead.
- If you only want to turn MCP off for one run, use `--no-mcp`, added in 1.0.4, which connects to no MCP server for that run.

This matches the idea of the [safety awareness](/en/guide/safety) lesson: for a read-only review task, you can withhold the file-writing tools from the Agent from the start. The command above only removes `write`, though; `bash` and `edit` can still change files, and `codemode` is not a permission boundary either. For a read-only exercise, enable only the read-only tools you need and combine that with isolation at the operating-system level.

## How the terminal knows what Pi is doing

OSC 7501 is the Program Status Protocol introduced by Mitchell Hashimoto on 6 October. Pi 1.1.0 reports five states following this protocol:

| State | When it appears |
| --- | --- |
| `working` | A task or a compaction is running |
| `blocked` | An extension dialog or a login is waiting for you |
| `done` | A run has ended |
| `error` | The run ended on an error that will not retry by itself |
| `idle` | Just started, or you cancelled the run |

The status report **contains no prompts and no model output**. Pi sends it only after the terminal answers the protocol's capability query; tmux and screen do not forward it. Set `PI_PROGRAM_STATUS=1` to force it on, or `0` to turn it off.

This matters most to people running several Pi sessions at once: a panel can read the status directly instead of guessing from the output on screen. In an ordinary terminal that does not implement the protocol, nothing on the interface changes, and nothing breaks.

## Changes in 1.0.1–1.0.4 that need action from you

| Version | Change | What to do |
| --- | --- | --- |
| 1.0.1 | The npm published package no longer pins indirect dependencies, and `pi update` suggests migrating a global npm install to the pi.dev installer | If you need pinned dependency versions, switch to the official installer; choosing an installation route is covered in [Installing Pi and opening it for the first time](/en/guide/install-pi) |
| 1.0.1 | `.pi/mcp.json` in a project can enable, disable, or adjust user-level MCP servers on its own | To turn off one server only inside one project, you no longer need to touch the global configuration |
| 1.0.3 | **The Azure provider was renamed**: `azure-openai-responses` became `azure` | If you use Azure, change the provider name in `auth.json` (or run `/login` again), `models.json`, and `settings.json` |
| 1.0.3 | `Home`/`End` always move the input-box cursor; jumping to the top or bottom of the fullscreen transcript moved to `Ctrl+Home`/`Ctrl+End` | If you were used to `Home`/`End` for the top or bottom of the transcript, switch to the new keys |
| 1.0.4 | `--tools` and `--exclude-tools` support `*` wildcards, and `--no-mcp` was added | For example, `--exclude-tools 'mcp__*'` turns off all MCP tools |

The Azure rename is an officially marked breaking change: a session restored under the old name switches to another model, and the prompt cache cannot be reused either. If you do not use Azure, skip this item.

## How do I check after upgrading?

First note the current `pi --version`, then upgrade along the same path your original installation used, as described in [Lifecycle management after installation](/en/guide/lifecycle-management). After upgrading, run this in a normal terminal:

```bash
pi --version
```

If it reproduces the version on this page, it should print `1.1.0`; if you update straight to the newest version, it may print something higher and you should check the matching changelog. Once you are inside Pi, confirm that your usual models still answer normally, that commonly used extensions still load, and that the MCP servers you need can connect.

To confirm that the plus/minus syntax took effect, do not just ask the Agent. First download and read this book's [tool-list check extension](/en/examples/tools/active-tools.ts) in your practice directory, and confirm that it only registers a command and reads tool names, with no file operations:

```bash
curl -fL https://pi.argakuka.com/en/examples/tools/active-tools.ts -o active-tools.ts
pi --tools +codemode,-write -e ./active-tools.ts
```

Once inside Pi, type `/bluebook-tools` in the edit area. This command reads Pi's tool registration state directly and does not call the model; the notification should include `codemode` and not `write`. If you have other extensions loaded, the list may be longer. This book verified it in a clean Pi 1.1.0 configuration and got `bash, codemode, edit, read`.

What this proves is the set of tools provided directly to the model, and you cannot use “writing a file failed” as the check: `bash` and `edit` can still change files, and Codemode can call other callable tools. If models, extensions, or MCP misbehave after the upgrade, keep the errors and the original configuration first, then work through [Troubleshooting](/en/reference/troubleshooting) one item at a time.
