# Pi 1.0.0 release highlights

Pi 1.0.0 was released on **1 October 2026**. This page is compiled from the official changelog, verified on **2026-10-02**. The complete item-by-item English changes are kept in the [release archive](/en/releases/#release-v1-0-0); what follows covers the changes you are most likely to meet in everyday use.

The [“Pi 1.0” release article](/en/translations/pi-1-0) discusses the overall result of the product reaching 1.0; some of those capabilities had already been added gradually before. The table below goes by **what the 1.0.0 changelog itself records**, so not every capability named in the release announcement counts as new that day.

## Changes worth noting

| Change | What it means for you |
| --- | --- |
| Full-screen terminal interface by default | On start, Pi takes the whole terminal; if you want the normal terminal scrollback to stay available, switch back to `regular` mode |
| Leaner Codemode prompts | In the official example, a GPT-5.6 request with Codemode enabled as a default tool drops from about 5,300 to 3,300 tokens; this does not mean total cost across all sessions fell by about 40% |
| Codemode can generate images | Scripts can call `models.generateImages()` using the session's credentials; generated images are attached to the result by `image()`, and their cost is charged to the session |
| Radius login entry point | `/login` offers Radius login, and after signing in you can configure the matching MCP server |
| Anthropic login by verification code | When the browser is on another machine, there is an option to log in by copying a verification code |
| Clearer tool errors | A misspelled tool name, model name, or argument format gives a more specific recovery hint |
| Leaner startup output | `quietStartup: "header"` keeps the version and key hints, and hides the rest of the startup resource list |

Codemode image generation only applies to the relevant image models and a configured provider; it does not mean every ordinary chat model can produce images. The figures in the table above come from configurations specified by the official notes and are not an independent Buku Pi performance test.

## Login, session, and interface fixes

MCP OAuth received several fixes in this version: validating the `iss` of the authorization response so that responses from the wrong authorization server are not accepted; handling empty optional fields; preserving existing scopes when adding permissions; and storing credentials per server name and per URL, so that different configurations of the same URL can use different accounts. Older credentials stored by URL alone are migrated to the first server that uses them.

When restoring a session and running `/reload`, deferred MCP tools already loaded by `tool_search` should no longer be lost to the ordering between a server reconnect and tool restoration. Other fixes cover the Apple Terminal startup flag, full-screen selection highlighting, command completion, and the memory used by long messages.

Also, **passing `--provider` without `--model` now fails with a clear error**, instead of quietly using another provider's default model. If your startup script is already written that way, add the matching model.

## How do I check after upgrading?

First note the current `pi --version`, then upgrade along the same path your original installation used, as described in [Lifecycle after installation](/en/guide/lifecycle-management). An existing installation can use the official CLI's `pi update`; an npm install needs Node.js 22.19.0 or later.

After upgrading, run this in a normal terminal:

```bash
pi --version
```

If it reproduces the version on this page, it should print `1.0.0`; if you update straight to the newest version, it may print something higher and you should check the matching changelog. Once you are inside Pi, confirm that your usual models still answer normally, that commonly used Extensions still load, and that the MCP servers you need can connect.

If you are not used to full-screen being the default, you can start it this way for now:

```bash
pi --tui-mode regular
```

You can also set `tuiMode` to `"regular"` in your existing settings. Do not overwrite the whole settings file just to add this one field.

If you maintain Codemode scripts, the old `typeof tools.name` way of probing for a tool needs to become `"name" in tools`.

## Pi Durable ships at the same time, but sits somewhere else

Pi Durable is an experimental application framework released at the same time, for Agent applications that run for a long time, recover persistently, and run many sessions. It does not replace the everyday Pi coding assistant, and it does not mean that after upgrading to 1.0.0 your existing tasks automatically gain the same recovery machinery.

To understand it further, start with the [Pi Durable primer](/en/guide/pi-durable), then read the [full official translation](/en/translations/pi-durable).
