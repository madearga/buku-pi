Today we are proud to release Pi 1.0: a thoroughly polished, minimalist, extensible Agent Harness that you can shape yourself. Every week, hundreds of thousands of people around the world use Pi. Many of you have filed issues and sent Pull Requests. Over the past few months we have kept improving, hardening, and evolving Pi from that feedback, making it stable software that individuals and companies alike can rely on.

Pi is known for being minimal, and we are careful to keep it that way. Agent tooling changes every week, but many changes do not last. Pi takes a different approach: we wait until something has proved its value before considering whether to adopt it, weighing what it actually provides against the complexity it inevitably adds. Earlier this week we [discussed that process further in this article](/en/translations/you-said-no-mcp), including how it relates to Codemode and MCP.

The Pi 1.0 released today is the result of that process. Pi can already run the latest models from the major providers, is the coding assistant people use every day all over the world, and also provides a highly malleable foundation for building Agent applications. Alongside the Pi 1.0 release, we are bringing the following capabilities to Pi:

- Codemode: native MCP support, and support for non-LLM models such as Jev and image models.
- Extensions can provide virtual models.
- Deferred tool loading.
- Cache warm-up for Anthropic models.
- Mid-conversation system messages: so that changes to prompts and tools show up in the transcript.
- A new terminal interface theme.
- Full-screen mode by default.

We had been thinking about most of these features for months. They were all tried, and in the end they stayed; there were far more experiments that did not. When we use Pi with these new features, we can feel it taking a big step forward, and yet it is still simple, still Pi.

While we kept polishing and evolving Pi, we also began to notice that some shapes of Pi do not suit the way many people want to use it. At Earendil, we want to carry Pi's minimalist principles, and the way Pi lets you take charge of AI, beyond the coding assistant and the terminal. It needs to be reachable from different interfaces, and to support conversations and tasks that run for longer. That means Pi needs to become more durable and reliable. So as not to drift from its minimalist roots, and not to force Pi into being something else, we packed that work into a new experimental package also released today: Pi Durable.

Pi Durable is a new foundation for building long-running Agent applications, so that the developers and users of those applications can flexibly use and steer the intelligence behind them. It shares Pi's core principles—minimalism and high malleability—while extending them into new dimensions. Mario explains [here](/en/translations/pi-durable) in detail how we built Pi Durable.

Earendil was founded to build software and open protocols that strengthen human autonomy. Today, we put the tools for reaching that goal into everyone's hands. We look forward to your feedback, and to mastering the future openly, together.

Pi 1.0 can be installed today:

``` sh
curl -fsSL https://pi.dev/install.sh | sh
```

Windows users can run:

``` powershell
powershell -c "irm https://pi.dev/install.ps1 | iex"
```

Pi Durable is also available today as an experimental package:

``` sh
npm install @earendil-works/pi-durable @earendil-works/pi-ai @earendil-works/chord
```

Both are MIT licensed. The documentation is at [pi.dev](https://pi.dev), and the code is at [github.com/earendil-works/pi](https://github.com/earendil-works/pi).

**Steps in the original terminal recording**

1. Codemode: Pi writes a script that turns a week of commits into a short summary.
2. Pi writes an Extension for itself: a virtual model that plans with Claude Opus first and then implements with GPT, with Jev deciding when to switch.
3. Reload, open a new session, and pick the new `router/auto` model.
4. Plan with Claude Opus.
5. Jev recognises that the work has entered implementation, and hands it to GPT 6 Luna.
6. Run the finished script with `!`.
7. `/session` shows cost and cache usage per model.

The original terminal recording can be played at [Earendil's Pi 1.0 page](https://earendil.com/posts/pi-1-0/).
