# Poin penting pembaruan Pi 1.1.0

Pi 1.1.0 dirilis pada **7 Oktober 2026**. Halaman ini disusun berdasarkan Changelog resmi dan dokumentasi versi terkunci, dengan tanggal verifikasi **2026-10-11**. Daftar lengkap perubahan per item berbahasa Inggris tersimpan di [arsip versi](/releases/#release-v1-1-0).

Antara 1.0.0 dan 1.1.0 ada empat versi kecil, yaitu 1.0.1 sampai 1.0.4. Jika Anda meningkatkan versi langsung dari 1.0.0, beberapa perubahan yang tercantum pada bagian belakang halaman ini juga akan Anda temui. Perubahan versi 1.0.0 itu sendiri lihat [Poin penting pembaruan Pi 1.0.0](/releases/pi-1-0).

## Perubahan yang layak diperhatikan pada 1.1.0

| Perubahan | Dampaknya bagi pengguna |
| --- | --- |
| Tool bawaan dapat ditambah dan dikurangi | Saat `--tools` ditulis sebagai daftar yang hanya berisi `+nama` dan `-nama`, tool bawaan ditambah atau dikurangi, bukan lagi diganti seluruhnya |
| Laporan status OSC 7501 | Terminal atau panel Agent yang mendukung protokol ini dapat melihat apakah Pi sedang bekerja, menunggu tindakan Anda, sudah selesai, atau gagal |
| Claude Haiku 5.5 | Menambah `anthropic/claude-haiku-5-5`, dengan tingkat penalaran tertinggi dapat mencapai `xhigh` / `max` |
| Model klasifikasi | GPT-6 Luna dapat dipakai sebagai model klasifikasi; `models.classify()` pada Codemode dapat menerima gambar, dengan syarat model klasifikasi yang dipilih mendukung gambar |
| `/mcp` tidak lagi menunggu semua koneksi | Saat antarmuka pengelolaan MCP dibuka, status koneksi server diperbarui secara waktu nyata, tanpa perlu menunggu semua server tersambung |
| `pi update` membersihkan versi lama | Untuk pemasangan yang dikelola installer resmi, setelah pembaruan hanya versi baru dan versi sebelumnya yang dipertahankan |

Model klasifikasi hanya bertugas menilai dan mengklasifikasi, bukan model utama untuk percakapan. Untuk obrolan sehari-hari dan penyuntingan kode, Anda tidak perlu mengubah pengaturan karena perubahan ini.

## Penulisan tambah-kurang tool bawaan

Pi mengaktifkan empat tool secara default, yaitu `read`, `bash`, `edit`, dan `write`. Dulu, untuk membuka satu tool lagi, Anda harus mendaftar ulang seluruh tool yang diinginkan; sejak 1.1.0, cukup menuliskan bagian yang ingin disesuaikan:

```bash
pi --tools +codemode,-write
```

Perintah ini mempertahankan tool bawaan lainnya, mengaktifkan `codemode` secara tambahan, dan menonaktifkan `write`. Tiga hal yang perlu diperhatikan:

- Nama biasa tidak boleh dicampur dengan penulisan `+`/`-`; begitu ada nama biasa, yang berlaku tetap penggantian dengan daftar lengkap.
- Setelah `+`/`-` hanya boleh ditulisi nama tool yang tepat, tanpa wildcard `*`; untuk menonaktifkan tool berdasarkan pola wildcard, gunakan `--exclude-tools`.
- Jika hanya ingin mematikan MCP sementara, gunakan `--no-mcp` yang baru ditambahkan pada 1.0.4; pada run kali ini tidak ada server MCP yang tersambung.

Gagasan ini sejalan dengan pelajaran [kesadaran keamanan](/guide/safety): untuk tugas review hanya-baca, Agent boleh tidak diberi tool penulis file sejak awal. Namun perintah di atas hanya menghapus `write`; `bash` dan `edit` tetap dapat mengubah file, dan `codemode` juga bukan isolasi izin. Saat membutuhkan latihan hanya-baca, aktifkan hanya tool hanya-baca yang dibutuhkan dan pasangkan dengan isolasi di tingkat sistem operasi.

## Bagaimana terminal tahu apa yang sedang dikerjakan Pi

OSC 7501 adalah Program Status Protocol yang diperkenalkan Mitchell Hashimoto pada 6 Oktober. Pi 1.1.0 melaporkan lima status mengikuti protokol ini:

| Status | Kapan muncul |
| --- | --- |
| `working` | sedang menjalankan tugas atau pemadatan |
| `blocked` | popup Ekstensi atau login menunggu Anda menangani |
| `done` | satu run berakhir |
| `error` | run berakhir karena galat yang tidak diulang otomatis |
| `idle` | baru saja dijalankan, atau Anda membatalkan run |

Laporan status **tidak memuat Prompt dan keluaran model**. Pi baru mengirimkannya setelah terminal menjawab query dukungan protokolnya; tmux dan screen tidak meneruskannya. Untuk memaksakan menyalakan, atur `PI_PROGRAM_STATUS=1`, dan untuk mematikan atur `0`.

Kemampuan ini paling berguna bagi yang membuka beberapa sesi Pi sekaligus: panel dapat membaca statusnya langsung tanpa menebak keluaran di layar. Terminal biasa yang tidak mengimplementasikan protokol ini tidak menampilkan perubahan apa pun, dan pemakaian tidak terpengaruh.

## Perubahan pada 1.0.1–1.0.4 yang perlu ditangani sendiri

| Versi | Perubahan | Yang perlu Anda lakukan |
| --- | --- | --- |
| 1.0.1 | Paket npm yang diterbitkan tidak lagi mengunci dependensi tidak langsung; `pi update` akan menyarankan migrasi pemasangan global npm ke installer pi.dev | Saat perlu mematok versi dependensi, beralihlah ke installer resmi; pemilihan cara instalasi lihat [Memasang Pi dan Membukanya untuk Pertama Kali](/guide/install-pi) |
| 1.0.1 | `.pi/mcp.json` di dalam proyek dapat mengaktifkan, menonaktifkan, atau menyesuaikan server MCP tingkat pengguna secara terpisah | Saat hanya ingin mematikan satu server di satu proyek, tidak perlu lagi mengubah konfigurasi global |
| 1.0.3 | **Provider Azure berganti nama**: `azure-openai-responses` menjadi `azure` | Pembaca yang memakai Azure perlu mengganti nama provider di `auth.json` (atau `/login` ulang), `models.json`, dan `settings.json` |
| 1.0.3 | `Home`/`End` selalu menggerakkan kursor area input; untuk lompat ke atas atau bawah riwayat pada layar penuh, gunakan `Ctrl+Home`/`Ctrl+End` | Yang terbiasa memakai `Home`/`End` untuk menggulir riwayat ke puncak atau dasar perlu beralih ke tombol baru |
| 1.0.4 | `--tools` dan `--exclude-tools` mendukung wildcard `*`, dan `--no-mcp` menjadi tambahan baru | Misalnya `--exclude-tools 'mcp__*'` menonaktifkan seluruh tool MCP |

Penggantian nama Azure termasuk breaking change yang ditandai resmi: sesi yang memakai nama lama akan beralih ke model lain saat dipulihkan, dan prefix cache-nya juga tidak dapat dipakai ulang. Pembaca yang tidak memakai Azure dapat mengabaikan item ini.

## Bagaimana memeriksanya setelah peningkatan?

Catat dulu `pi --version` saat ini, lalu tingkatkan versi lewat jalur yang sesuai dengan cara instalasi awal Anda seperti dijelaskan di [pengelolaan siklus hidup](/guide/lifecycle-management). Setelah meningkatkan versi, jalankan di terminal biasa:

```bash
pi --version
```

Saat mereproduksi versi yang sesuai dengan halaman ini, hasilnya menampilkan `1.1.0`; jika nanti langsung diperbarui ke versi terbaru, hasilnya bisa lebih tinggi dan Anda perlu memeriksa changelog yang sesuai. Setelah masuk ke Pi, pastikan model yang biasa dipakai masih menjawab dengan normal, Ekstensi yang umum dipakai masih dapat dimuat, dan server MCP yang dibutuhkan dapat terhubung.

Untuk memastikan penulisan tambah-kurang tool berlaku, jangan hanya bertanya kepada Agent. Unduh dan baca dulu [Ekstensi pemeriksa daftar tool](/examples/tools/active-tools.ts) milik buku ini di direktori latihan, dan pastikan ia hanya mendaftarkan perintah serta membaca nama tool, tanpa operasi file:

```bash
curl -fL https://pi.argakuka.com/examples/tools/active-tools.ts -o active-tools.ts
pi --tools +codemode,-write -e ./active-tools.ts
```

Setelah masuk ke Pi, ketik `/bluebook-tools` di area edit. Perintah ini membaca status registrasi tool Pi secara langsung tanpa memanggil model; pemberitahuannya seharusnya memuat `codemode` dan tidak memuat `write`. Jika masih ada Ekstensi lain, daftarnya bisa lebih panjang. Buku Pi memverifikasinya pada konfigurasi bersih Pi 1.1.0 dan mendapat `bash, codemode, edit, read`.

Yang dibuktikan adalah himpunan tool yang disediakan langsung kepada model, jadi “gagal menulis file” tidak boleh dipakai sebagai verifikasi: `bash` dan `edit` tetap dapat mengubah file, dan Codemode masih bisa memanggil tool lain yang dapat dipanggil. Jika model, Ekstensi, atau MCP bermasalah setelah peningkatan versi, simpan dulu pesan galat dan konfigurasi aslinya, lalu periksa satu item dalam satu waktu sesuai [penanganan masalah](/reference/troubleshooting).
